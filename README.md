# Rush — موقع الرغبات والمواعيد

## التشغيل

1. ثبّتي Node.js ثم شغّلي `npm install`.
2. انسخي `.env.example` إلى `.env` واملئي إعدادات Supabase ورابط المجموعة وتعليمات الدفع.
3. في Supabase: أنشئي مشروعًا، وافتحي SQL Editor، وانسخي محتوى `schema.sql`. **قبل التنفيذ** استبدلي `REPLACE_ADMIN_EMAIL` ببريد الإدارة الحقيقي داخل SQL.
4. من Supabase Authentication > Users أنشئي مستخدمة الإدارة بالبريد نفسه وكلمة مرور قوية. ضعي البريد في `VITE_ADMIN_EMAIL`. فعّلي إعدادات الأمان ومحددات المعدل في Supabase.
5. شغّلي `npm run dev`. لعمل نسخة إنتاجية: `npm run build`، وانشري مجلد `dist` على Netlify، مع متغيرات البيئة.
6. صفحة الإدارة: `/ادارة` أو `/admin` (تعمل عند تفعيل إعداد إعادة التوجيه `netlify.toml`).

## مهم قبل الإطلاق

- بدون Supabase يظهر تصميم تجريبي وأمثلة مواعيد، **ولا تُحفظ أي بيانات**. لا تنشريه باعتباره نظام حجوزات جاهزًا قبل الربط والاختبار.
- الاسم والجوال ليسا إثبات هوية؛ القيد يمنع نفس الرقم من تكرار التسجيل في الموعد لكنه لا يمنع استخدام أرقام أخرى أو انتحال رقم. يوصى بإضافة OTP عند الحاجة.
- الواجهة العامة لا تعرض أرقام الجوال. صفحة الإدارة محمية بالمصادقة وRLS. لا تضعي `service_role` في ملفات الواجهة.
- يمكن إساءة استخدام نماذج التسجيل العامة. أضيفي rate limiting / CAPTCHA وحماية ضد الروبوتات قبل النشر العام.
- بيانات الدفع تظهر بعد طلب الانضمام؛ الدفع لا يُتحقق منه تلقائيًا ولا يعني تأكيد الحجز.
- يُفضّل إضافة سياسة خصوصية قصيرة، مدة احتفاظ للبيانات، وإجراءات حذف البيانات قبل جمع أرقام الجوال الحقيقية.
- يجب تعديل ألوان CSS عند توفر قيم ألوان هوية Rush الدقيقة؛ المستخدمة حاليًا لوحة وردية تقريبية مستوحاة من المراجع.
## تحديث 12 نوفمبر 2026

للمشاريع القائمة في Supabase: شغلي ملف [supabase-migration-2026-11-12.sql](./supabase-migration-2026-11-12.sql) مرة واحدة من SQL Editor قبل استخدام تبويب **الإعدادات** في صفحة /ادارة. يضيف تعليمات الدفع ورابط المجموعة ويتيح فترتي ٥–٧ و٧–٩ مساءً بدل صباحًا/عصرًا/مساءً. لا تعيدي تشغيل schema.sql القديم على قاعدة بيانات قائمة.

تُحفظ إعدادات الدفع والمجموعة في قاعدة البيانات وتظهر للزائرات (تعليمات الدفع بعد تقديم الطلب). لا تضعي بيانات خاصة في حقل التعليمات سوى ما تريدين عرضه للمتقدمات.


## تحديث المناطق والأسعار والحذف التلقائي

التعديلات في `src/main.jsx` و`src/style.css` و`public/riyal.svg` تحتاج **خطوتين في Supabase قبل استخدامها**:

1. افتحي **SQL Editor → New query** وشغّلي ملف [supabase-migration-regions-prices-cleanup.sql](./supabase-migration-regions-prices-cleanup.sql). يضيف الأعمدة، تحديث حفظ رغبات اللاعبات، عملية الحذف الآمنة من الإدارة، وعرض السعر والمنطقة للزائرات. لا يحذف التسجيلات أو المواعيد القائمة. **لا تشغّلي `schema.sql` القديم على المشروع القائم.**
2. للحذف التلقائي الحقيقي بعد انتهاء **يوم** الموعد بتوقيت الرياض، شغّلي [supabase-enable-daily-cleanup.sql](./supabase-enable-daily-cleanup.sql) عبر SQL Editor بعد الخطوة الأولى. يستخدم `pg_cron` عند **00:10 صباحًا بتوقيت الرياض**. إذا رفض Supabase تفعيل `pg_cron`، فعّليه من **Database → Extensions** ثم أعيدي تشغيل الملف. لا يمكن للجداول حذف نفسها بمرور الوقت من دون تشغيل المهمة المجدولة.

**لاحظي:** المواعيد القائمة تُحفظ وتظهر بسعر افتراضي `0` ومنطقة غير محددة حتى تفتحيها من الإدارة وتضبطي السعر والمنطقة الحقيقية. الرغبات القديمة كذلك ستظهر بدون منطقة لأن الاختيار جديد. بإمكان اللاعبة إرسال رغبات متعددة وتعديل مناطق نفس الرغبة. حذف الرغبة يدويًا يتطلب تأكيدًا، ومسموح فقط لحساب الإدارة.


## إجراءات الرغبات في الإدارة

بعد تحديث واجهة Rush، نفّذي [supabase-admin-wish-actions.sql](./supabase-admin-wish-actions.sql) في **Supabase → SQL Editor → New query → Run**. يتطلب أن يكون [تحديث المناطق والأسعار](./supabase-migration-regions-prices-cleanup.sql) قد نُفّذ قبله. يتيح للإدارة وحدها تعديل رغبة محددة وحذف كل الرغبات يدويًا. زر الحذف الجماعي يحتاج تأكيدًا إضافيًا وكتابة كلمة «حذف»، ولا يمس المواعيد أو تسجيلات اللاعبات. لا تُحذف أي رغبات عند مجرد تشغيل ملف التحديث.
